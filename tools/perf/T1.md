# T1 performance dry run

The frozen production parent is `bb0fea399793eb2aeb1ae93d5972763b9761da98`.
Use the same prebuilt `main.rs`/`driver.rs` binary for both labels. Do not use
`baseline_main.rs`, `--baseline`, `--parent-compatible`, the B2 shell wrappers,
or their 509cf9b defaults. Record the T1 measurement harness overlay separately

The native pilot is `demo1-dense`: execute and present frames 1–1519, discard
1399 warmup frames, observe 1400–1519. Each label gets five fresh processes in
AB, BA, AB, BA, AB order. One attempt contains exactly ten invocations; every
invocation has fresh resting calibration, 30-sample preflight, continuous
telemetry, and ten-sample postflight through `protocol.py` `b2-quiet-v4`.
After driver controls, the wrapper records one throwaway full-prefix shader
warm-up, then a fixed 90-second settle before the first resting calibration.

V4 applies only to `native.demo1-dense` coarse timing. Each revision's observed
CPU and elapsed spreads, `(max-min)/median` of per-run means, must be at most
0.25 and 0.15. Aggregate cold-prefix CPU and elapsed retain 0.05 ceilings.
Assembly and component spreads are diagnostic for this cell. The other nine
native/Chrome rows and counter configurations use `b2-quiet-v3` and its 0.05
spread checks. The row manifest records the policy for each configuration.

V4 uses a fixed 0.75-core consecutive-sample background ceiling in preflight,
run and postflight, including phase-boundary history. Rolling 30-sample
background means, resting-derived idle floors, dirty-calibration limits,
named process ceilings, prohibited jobs, thermal/power/swap checks, monitor
gaps and completeness checks still apply. No additional process is exempt.

CPU totals are divided by recorded frames and elapsed totals by recorded
emission intervals. Both absolute floors are frozen at 0.01 ms per frame;
a total's equivalent floor is 0.01 times its denominator. For each cold and
observed metric, `U = max(parent range, candidate range, 0.01 ms)`. Five
positive candidate-minus-parent deltas with median above U resolve a regression
and fail admission. Five negative deltas with median savings above U resolve
a speedup. The identical-binary validation rejects either direction. A passing
comparison without a resolved speedup says only “no regression resolved above U.”
Spread ceilings are not permitted slowdown percentages.

Batch, pilot and replay verdicts name the policy and report lost sensitivity
in ms per frame and as a fraction of the batch's parent median. Rejected
batches retain descriptive ranges from all available timing, including rejected
runs; missing values are never imputed. No incomplete or rejected pair passes.
Retain startup/device/setup costs, first-frame and shader-compile observations
for the separately frozen cold-cost gates before T2. Warm-up cannot waive them.

V4 code-change batch plans require `validation_verdict: {"path": "...",
"sha256": "..."}` pointing to the passing v4 parent/parent pilot verdict.
The native wrapper only performs the parent/parent validation. Counted-work
gates in `tools/tmem/dispatch-expectations.json` remain required alongside
coarse timing; counts alone do not close C1 or establish a speedup.

## Validation decision

The reservation ledger counts the external pre-kit v3 window and the retained
kit v3 window. It rejects another v3 reservation. Only the recorded acceptance
permits `window3-v4-validation`; an interrupted allocation consumes that slot.
Any failed validation stops for a new protocol decision and separately
accepted reservation. Retain failed windows under their original names.

```sh
python3 tools/perf/t1.py decision --root "$T1_WINDOWS" --out "$T1_FRESH_DECISION"
python3 tools/perf/replay_batch.py --attempt "$T1_WINDOW/native-demo1-dense" \
  --policy b2-quiet-v4 --backend native --out "$T1_FRESH_REPLAY"
```

The decision admits only a passing v4 verdict from that named reservation.
It reports the batch's lost sensitivity, the separate ci4 Chrome driver
requirement, and `full_t1_valid: false`. Native validation alone does not close
the full timing/count/cold matrix or T1. Retrospective replay writes fresh
outputs, preserves original verdicts and always reports `timing_valid: false`.
Use `--policy b2-quiet-v3` to reproduce the v3 telemetry rule.
