## Claude's assembly and execution

The complete executable assembly commands are in
`/Volumes/DS Vault/hub/scratch/fast3d/tmem-checks/T2/performance-round1/assemble-bundle.py`.
The script refuses existing checkout/build/bundle directories, archives the two
production SHAs into fresh physical source trees, builds each with this same
measurement harness, records compiler/dependency/source/binary provenance,
relinks Nix libiconv to `/usr/lib/libiconv.2.dylib`, re-signs, verifies the
signature and system-only dynamic dependencies, then freezes and archives the
payload. It reuses the authenticated T1 captures/source/Python distribution.
It requires no GPU and installs nothing on the worker.

Run on ci4:

```sh
cd '/Volumes/DS Vault/hub/wt/fast3d-rs-perf'
devenv shell -- python3 '/Volumes/DS Vault/hub/scratch/fast3d/tmem-checks/T2/performance-round1/assemble-bundle.py'
```

The two configure commands executed by that script are:

```sh
python3 '/Volumes/DS Vault/hub/wt/fast3d-rs-perf/tools/perf/configure.py' \
  --assembler '/Users/ci/hub/repos/n64.toys' \
  --library '/Volumes/DS Vault/hub/scratch/fast3d/tmem-checks/T2/performance-round1/checkout-parent/fast3d' \
  --out '/Volumes/DS Vault/hub/scratch/fast3d/tmem-checks/T2/performance-round1/build-parent'
python3 '/Volumes/DS Vault/hub/wt/fast3d-rs-perf/tools/perf/configure.py' \
  --assembler '/Users/ci/hub/repos/n64.toys' \
  --library '/Volumes/DS Vault/hub/scratch/fast3d/tmem-checks/T2/performance-round1/checkout-candidate/fast3d' \
  --out '/Volumes/DS Vault/hub/scratch/fast3d/tmem-checks/T2/performance-round1/build-candidate'
```

For each generated manifest the script runs `cargo build --offline --release
--manifest-path <build>/Cargo.toml` with a separate `CARGO_TARGET_DIR`, then:

```sh
/usr/bin/otool -L "$T2_BINARY"
/usr/bin/install_name_tool -change "$T2_NIX_LIBICONV" /usr/lib/libiconv.2.dylib "$T2_BINARY"
/usr/bin/codesign --force --sign - "$T2_BINARY"
/usr/bin/codesign --verify --strict "$T2_BINARY"
/usr/bin/otool -L "$T2_BINARY"
```

`T2_NIX_LIBICONV` is each actual Nix libiconv path found by `otool`, not a guessed
store hash. The final signed bytes are the ones hashed into each build record.
The parent and candidate use the same harness sources; neither uses `--baseline`.
